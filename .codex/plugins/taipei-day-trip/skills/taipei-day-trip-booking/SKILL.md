使用台北一日遊 MCP 搜尋台北市景點、確認景點編號與行程日期時段、建立待付款預訂，最後提供 Booking 頁面。當使用者想搜尋台北景點、安排台北一日遊或預訂導覽行程時使用。

# 台北一日遊預訂流程

全程使用繁體中文與使用者互動。一次只詢問目前步驟需要的資訊，不自行假設景點、日期或時段。

## 1. 詢問搜尋條件

先請使用者輸入想搜尋的台北景點名稱、關鍵字或捷運站名稱，並提供簡短例子，例如「北投」、「台北101」或「中正紀念堂」。

## 2. 搜尋並列出景點

呼叫台北一日遊 MCP 的 `search_attractions` 工具，將使用者的原始搜尋文字放入 `keyword`。

搜尋成功後，使用純文字條列清單顯示所有結果，不要使用表格或圖表。

每筆固定使用以下格式：

`景點 ID｜景點名稱｜分類｜最近捷運站`

例如：

`1｜新北投溫泉區｜養生溫泉｜新北投站`

分類、地址或捷運站缺少時，顯示「未提供」。可以在必要欄位後補充景點描述。

若沒有搜尋結果，請使用者更換關鍵字，不要進入預訂流程。

若工具回傳 `error: true`，請告知使用者搜尋失敗，並請使用者稍後再試。

## 3. 確認景點

請使用者從搜尋結果中選擇一個景點 ID。

只能接受剛才搜尋結果中實際存在的景點 ID；如果使用者輸入其他 ID，請重新詢問。

## 4. 詢問日期與時段

確認景點後，請使用者用自然語言提供預約日期與上午或下午時段。

可以接受：

- `2026/09/20 上午`
- `2026年9月20日下午`
- `九月二十號下午`

呼叫工具前，必須轉換成以下格式：

- `date`：`YYYY-MM-DD`
- `time`：上午使用 `morning`，下午使用 `afternoon`
- `price`：上午固定為 `2000`，下午固定為 `2500`
- `attraction_id`：使用者選擇的整數景點 ID

日期不得早於今天。日期不完整、可能跨年或意思不清楚時，先向使用者確認，不可以自行猜測。

## 5. 建立待付款預訂

呼叫台北一日遊 MCP 的 `add_to_cart` 工具，傳入：

- `attraction_id`
- `date`
- `time`
- `price`

若工具回傳 `error: true`，請告知使用者可能是 Bearer Token 無效或資料格式錯誤，並請使用者到會員中心重新產生 Token。

## 6. 引導至付款頁

預訂成功後，使用繁體中文顯示：

- 景點名稱與編號
- 預約日期
- 上午或下午
- 台幣價格
- 工具回傳的 Booking Page URL

提醒使用者開啟 Booking Page URL，確認行程和聯絡資料後完成付款。

預設正式付款頁為：

`http://13.112.91.227:8000/booking`

不要向使用者顯示或要求輸入 Bearer Token。
